# Cloudflare DNS-01 多账号证书设计

## 目标与边界

在保留现有 HTTP-01、证书目录、cron 重试机制及中文交互的前提下，增加 Cloudflare DNS-01。它用于公网 80 端口不可达的服务器，以及 `*.example.com` 通配符。一个输入域名对应一张独立证书，不把多个输入域名合并进一张证书。新域名首次申请时由管理员选择验证方式；DNS-01 还须明确选择预先保存的 Cloudflare 账号编号。成功后记录绑定，手动及自动续期始终使用此编号，不根据 DNS 记录猜账号，也不在失败时切换账号。

首版只支持 Cloudflare，不支持自动发现账号、批量导入、自动重载服务或通用密钥加密。Token 在 root 权限的本机文件中保存，acme.sh 也可能在自己的配置中保存副本。没有另一个可用的解密密钥管理服务时，自动续期所需的 Token 无法靠本机可自动解密的文件获得实质性静态保护；因此不宣称已加密，不上传 Token 到本项目的服务端或 GitHub。

## 命令与交互

- `w ssl` 的申请入口先选择 HTTP 或 Cloudflare DNS；HTTP 沿用现有 IPv4/IPv6/双栈提示和行为。DNS 入口输入一个普通域名或一个 `*.` 开头的通配符，再列出账号编号及自定义名称供选择。一次输入多个域名时，逐个完成选择与申请，逐个生成证书；一个失败不覆盖其他域名的证书。首版命令行每次仅申请一个域名，多域名由菜单重复操作，不引入逗号分隔解析。
- 新增账号管理入口，提供添加、查看编号和名称、测试、更新 Token、删除。CLI 提供对应子命令，并同步更新菜单、帮助、安装提示及 README。编号是稳定的不重复正整数，名称仅供辨识；任何展示和测试结果不得输出 Token 或其片段。输入 Token 使用隐藏回显的交互式提示，首版不支持把 Token 放在命令参数中。
- 已管理域名再次申请时读取保存的验证方式及账号编号；如与本次显式请求不一致，拒绝静默改绑。更换账号须通过单独的显式改绑操作，先验证目标账号可操作域名，再写入绑定。失败不改变原绑定；现有证书保持不变。
- 证书列表和状态展示验证方式及 DNS 账号编号/名称，不展示 Token；删除域名证书后同时删除该域名的绑定，不删除共享账号。删除账号前检查是否仍有域名绑定；存在绑定时拒绝删除并列出域名。

## 本机状态与凭据

- 沿用 `/etc/letsencrypt/live/<domain>/fullchain.pem` 和 `privkey.pem`；现有 HTTP 证书继续使用 `/etc/letsencrypt/ssl-certbot/<domain>.conf` 的网络模式。新增每域名的验证方式和 DNS 账号编号，采用受限的纯数据格式读取，不 `source` 配置文件；缺失这些新字段的旧证书一律按 HTTP-01 旧逻辑处理。
- Cloudflare 账号索引和每个编号的 Token 分开保存在 `/etc/letsencrypt/ssl-certbot/` 下的受限目录。编号和名称不作为脚本代码执行；名称、域名和编号均做输入校验。目录权限 `0700`、配置及 Token 文件 `0600`，写入时使用限制权限的临时文件并原子替换。权限异常时拒绝申请/续期并给出可操作错误。
- DNS 账号的 acme.sh 配置及证书记录彼此隔离，HTTP 的现有 `/root/.acme.sh` 不迁移、不改写。每次调用 acme.sh 都明确选择对应账号的配置位置并从该账号的受限 Token 文件提供 Cloudflare 环境变量，禁止从另一账号的持久配置回退取 Token。实现前以 acme.sh 的实际参数及 `dns_cf` 插件行为确认配置隔离；如无法可靠隔离，则不启用多账号申请，而非冒险串用凭据。Token 更新必须同步清除或替换 acme.sh 保存的旧值，不能只更新本项目文件。
- Token 只在目标 VPS 上使用：Cloudflare API 用于域名权限测试、TXT 写入与清理，Let's Encrypt 用于签发。禁止 `set -x`、在参数中携带 Token、记录环境变量或把 Token 写入普通日志；acme.sh 原生日志、账号配置与备份也按敏感文件保护。文档说明 root、备份软件及具有相应权限的本机进程仍可能读取明文，不宣传绝对不泄漏。

## 签发与续期流程

DNS-01 申请先确认账号编号存在、Token 可用且有目标 zone 的访问/编辑权限，再由 acme.sh `dns_cf` 完成 `_acme-challenge` TXT 的创建、传播验证及清理。DNS-01 不执行 A/AAAA 到本机地址的预检，也不扫描、停止或恢复 80/443 监听者；保留签发后安装证书、权限检查和 cron 配置。普通域名与合法的 `*.` 前缀域名只允许 DNS 路径的通配符；拒绝任意位置的 `*`、空标签、路径及 shell 特殊输入。

证书成功签发并安装、账号绑定持久化后，才报告完整成功。签发成功但安装或绑定失败时明确报告部分成功、保留现有可用证书与 acme.sh 记录供修复，不把它纳入自动续期；不得把失败伪装为成功。CLI 和菜单提示用户 DNS-01 无须开放 80 端口，也不会自动重载使用证书的服务。通配符证书仅覆盖单层子域名，不自动覆盖根域名；根域名要有独立证书。

续期先按证书逐个读取验证方式：DNS 证书检查绑定及账号文件后使用原编号的 Token 和独立 acme.sh 状态续期，全程不操作端口；HTTP 证书继续按保存的网络模式续期。批量续期仅在确有待续期的 HTTP 证书时执行原有端口安全预检及暂停/恢复；DNS 证书即使 HTTP 预检失败也仍逐个尝试，汇总返回非零以触发原有 8 小时重试。绑定缺失、账号删除、权限不足或 Cloudflare API 错误时只失败该证书，不猜测其他账号。手动指定域名续期也遵循相同分流和到期窗口。

## 兼容、删除与验证

更新脚本不得覆盖账号文件、域名绑定、现有证书和 acme.sh 状态；卸载默认保留上述用户数据并明确告知；删除证书仅删除所选域名在正确 acme.sh 账号下的记录及部署文件，不能清除其他账号的记录。旧证书没有新增绑定时默认保持 HTTP 行为；不自动转换为 DNS。编号即使删除也不复用，防止旧绑定指向另一个 Token。
